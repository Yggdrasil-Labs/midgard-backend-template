# 客户 HTTP 响应与错误统一约定

**归属版本**：1.3.0

对外字段、状态码与错误码以[跨项目 API 契约](../../../design-docs/arch-api-contract.md)为唯一来源。本文约束本需求的客户行为；技术实现见[设计](design.md)，任务与验证见[计划](plan.md)。

## 范围

统一现有客户创建、详情、列表、更新、删除五个接口的响应与错误，补齐输入边界。不改变 URL、业务字段、过滤条件或 ID 数字类型。版本字段及真实版本冲突由 `data-consistency` 交付；前端和 E2E 项目不在本次修改范围。

## Behavior：创建客户

| Scenario | Given | When | Then |
| --- | --- | --- | --- |
| 正常 | 姓名“张三”、合法未占用邮箱、电话“13800000000” | 提交创建 | HTTP 200、`code=00000`、`success=true`，返回数字 ID、原姓名邮箱及 ACTIVE 状态 |
| 长度边界 | 合法邮箱长 100、电话长 20 | 提交创建 | 接受请求；电话未提供或为 null 时也可创建，返回的空电话字段为 null |
| 参数错误 | 邮箱长 101、电话长 21 或姓名长 1 | 提交创建 | HTTP 400、`code=00004`，明细包含对应字段；请求不进入写入用例 |
| 邮箱冲突 | 邮箱已被其他客户占用 | 提交创建 | HTTP 200、`code=21001`、`success=false`、`data=null`；预检查与写入时发现冲突具有相同对外结果 |

## Behavior：查询客户详情

| Scenario | Given | When | Then |
| --- | --- | --- | --- |
| 正常 | ID 42 的客户存在 | 查询 42 | HTTP 200、`00000`，返回 ID 42 的客户 |
| 空值边界 | 客户电话为空 | 查询该客户 | `data.phone` 存在且为 null，公共信封字段仍存在 |
| 不存在 | ID 999 不存在 | 查询 999 | HTTP 200、`20001`、`data=null`，与接口路由不存在的 HTTP 404 区分 |

## Behavior：分页查询客户

| Scenario | Given | When | Then |
| --- | --- | --- | --- |
| 正常 | 共 23 条匹配记录，页码 2、大小 10 | 查询列表 | HTTP 200、`00000`，列表位于 `data.data`；总数 23、总页数 3、有上页及下页 |
| 纠正边界 | 页码 0、大小 1001 | 查询列表 | 使用页码 1、大小 1000 查询并原样回报该组分页参数；缺省/无效小值按契约纠正 |
| 空集合 | 没有匹配记录 | 查询第 1 页 | HTTP 200、`00000`，列表为 []、总数及总页数均为 0，前后页标记均为 false |
| 非法输入 | 页码为非数字或超过 2147483647，或状态为 UNKNOWN | 查询列表 | HTTP 400，不接受非法查询；有效关键词/状态的过滤与 ID 降序保持原语义 |

## Behavior：更新客户

| Scenario | Given | When | Then |
| --- | --- | --- | --- |
| 正常 | ID 42 存在 | 只提交姓名“李四” | HTTP 200、`00000`，姓名更新，未提供或为 null 的其他字段不改变 |
| 边界 | 邮箱未变，或电话提交空字符串 | 提交更新 | 未变邮箱不作为重复；电话允许清空为字符串 ""，空值 null 仍表示不更新 |
| 空更新 | 姓名、邮箱、电话均未提供或均为 null | 提交更新 | HTTP 400、`00004`，对象级错误 `source=OBJECT,path=$`，不进入写入用例 |
| 字段无效 | 姓名/邮箱为空白，邮箱长 101 或电话长 21 | 提交更新 | HTTP 400、`00004`，字段级错误指向对应字段，不接受变更 |
| 业务错误 | 客户不存在，或目标邮箱被他人占用 | 提交非空更新 | 分别返回 HTTP 200 + `20001` / `21001`，`data=null` |

## Behavior：删除客户

| Scenario | Given | When | Then |
| --- | --- | --- | --- |
| 正常 | ID 42 存在 | 删除 42 | HTTP 200、`00000`、`success=true`，信封中明确包含 `data:null` |
| 重复操作 | 首次删除已成功 | 再次删除相同 ID | HTTP 200、`20001`；不承诺重复删除仍成功 |
| 参数错误 | 路径 ID 不是数字 | 提交删除 | HTTP 400，错误信封符合公共契约，不进入删除用例 |

## Behavior：公共错误与追踪

| Scenario | Given | When | Then |
| --- | --- | --- | --- |
| 正常增强 | 请求携带合法追踪 ID `contract-42` | 得到成功或异常响应 | `X-Trace-Id` 与信封 `traceId` 均为 `contract-42`；`timestamp` 为数字 |
| 请求体错误 | 请求体是损坏 JSON | 提交创建/更新 | HTTP 400、`00004`、`data=null`，消息不回显请求体 |
| 未知异常 | 处理期间发生未知服务端异常 | 生成错误响应 | HTTP 500、`10000`、`success=false`，消息不包含内部异常、SQL、连接或凭据内容 |

## 约束与证明边界

- 姓名 2–50、邮箱合法且不超过 100、电话可选且不超过 20，沿用现有字段容量及姓名下限；不新增电话格式规则。
- 分页缺省 1/10，小于 1 纠正为 1/10，大小上限 1000；页码上限 2147483647 延续当前整数仓储的表示范围。
- 只编写单元、standalone MockMvc、序列化及架构测试，不启动完整应用、数据库或容器。隔离测试中的写入拒绝、冲突与追踪夹具不作为真实数据库、并发或自动装配已验证的证据。
- 本项仅验证 `21002` 的错误信封映射；不新增 `version`，不声称已具备乐观锁。跨项目破坏沿用已有决定，不增加旧信封兼容层。
