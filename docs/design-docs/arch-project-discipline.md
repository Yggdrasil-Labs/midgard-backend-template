# 文件约束与项目纪律 RFC

## 背景与授权范围

本轮用户明确要求参考 Mimir Boot 的 docs 优化后端文件约束与项目纪律，并允许淘汰不必要的 Markdown，CI 不在范围内。参考基线为本地 Mimir Boot `8d33639` 的文档治理、开发指南与工具准入规则。

Midgard 当前已有架构、工程信条和技术债清单，但缺少统一文档入口及文件归属规则。导航含不存在的目录，部分页面将预留能力写为已完成；新增文档和临时产物也缺少明确落点。

## 方案与取舍

- AGENTS 维护硬约束与阅读地图，文档总索引按任务导航；治理规范定义文件归属，开发指南说明工作步骤。
- 现有架构、领域、安全、可靠性和工程信条保留路径，新规范进入 `docs/standards/`，操作指南进入 `docs/engineering/`。现有文件职责清晰后无需仅为目录一致而迁移。
- 同一事实保留一个维护位置；当前规范直接维护有效状态，历史依据和执行证据进入需求记录或归档。
- 文件按持续用途准入，限制一次性报告、脚本及重复说明入库；已有业务回归测试和必要测试资源继续由所属模块维护。
- 生成文档实际存在后才登记来源与生成方式；缺失产物作为技术债跟踪，不保留空索引。

这些规则落实已有“入口简短、文档服务执行、区分事实与扩展位”的信条，并将“显式评分”调整为“可核实证据”；不改变模块依赖方向、运行行为或技术栈。

## 文档收敛

| 淘汰内容 | 保留方式 |
| --- | --- |
| 独立产品思维页 | 模板能力准入原则并入工程信条 |
| 陈旧质量评分卡 | 缺口继续由技术债跟踪，验证纪律由开发指南维护；不保留缺少评估依据的分数 |
| 空生成文档注册表 | 缺失产物继续由 TD-002 跟踪，治理规范定义生成要求 |
| 迁移目录重复 README | 必要说明与历史文档入口合并到该目录索引 |
| 已过时的入门旅程 | 当前使用路径由 README、开发指南和领域文档承接 |
| 本轮独立执行计划 | 文档变更的取舍与验收集中于本 RFC，不重复保留过程页 |

## 边界

不引入 Mimir 的 Starter 目录约定、Node 初始化方式、工程脚本、Git hook、CI 或发布门禁。文件检查不自动安装工具，也不授予提交、推送或发布权限。文档仍需人工核对语义，本轮不声称已建立持续自动校验。
