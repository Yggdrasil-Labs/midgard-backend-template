# 设计决策目录

本目录保存跨需求的实际架构设计与关键技术取舍。每份文档应说明需要解决的技术问题、候选方案、采用理由、影响范围及验证依据。

当前核心分层由 [ARCHITECTURE](../../ARCHITECTURE.md) 维护，尚无另行维护的跨需求设计条目。

工程原则见[工程信条](../standards/core-beliefs.md)，文档组织与维护见[文档治理](../standards/documentation-governance.md)。单个需求的设计放在所属版本需求目录；日常规则调整和治理过程说明不作为本目录的设计条目。

## status 含义

- **draft**：设计尚未落地。智能体可参考但需注意细节可能变化。
- **verified**：设计与当前实现一致，并有与声明范围相符的验证依据；不代表所有运行或发布场景均已验收。
- **stale**：实现已偏离设计。智能体不应信赖细节，需先更新。

## 如何添加

1. 确认存在需要独立记录的架构决策及长期使用者；能由现有文档表达时直接维护原位置。
2. 使用[设计模板](_template.md)填写实际问题、方案取舍和证据，移除无关章节与占位内容。
3. 在本页登记主题、状态、适用范围及路径，初始状态为 draft。
4. 设计落实并完成相应验证后再标记 verified；实现偏离时重新核对并维护状态。
