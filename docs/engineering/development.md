# 开发与协作指南

面向 Midgard 维护者及 Agent。模板使用方法见 [README](../../README.md)，文件与文档准入见[治理规范](../standards/documentation-governance.md)。

## 开始工作

1. 确认仓库根目录和 `git status --short`，识别并保留已有改动。
2. 阅读目标实现、相关测试和对应约束，明确当前行为、目标行为与可验证例子。
3. 确定涉及的层、文件和兼容边界。按任务规模准备计划；新增文件前明确持续用途，不为局部修改建立整套过程文档。
4. 使用项目实际环境与 Maven Wrapper。WSL 的 Node、Java、Python 由 mise 管理，项目配置和当前 mise 状态优先；需要时显式使用 `mise exec -- <命令>`，不假定子进程继承了登录 shell 环境。

## 定位修改位置

| 改动 | 文件归属与检查范围 |
| --- | --- |
| HTTP 请求、响应、参数校验 | Adapter 的 Controller、Request、Convertor；同时检查前端或实际调用方 |
| 用例编排、事务、应用输出 | App 的 AppService、Cmd/Qry、CO、Assembler；按复杂度拆分 Executor |
| 业务规则、领域模型 | Domain；新增对象遵循现有聚合命名与依赖边界 |
| 持久化、外部系统集成 | Infrastructure 的 Repository 实现、DO、InfraConvertor 与适用 Gateway |
| 跨服务契约 | Client；当前仅有包结构预留，新增接口或 DTO 时同步使用方与兼容说明 |
| 装配与运行配置 | Start；不把业务规则放入启动模块 |
| 数据库结构 | 当前 Flyway 从 Start 的 `classpath:db/migration` 读取；根 `db/migration/` 另有副本，修改前核对两处，唯一维护源尚待确定 |
| 回归测试 | 所属模块 `src/test/`；完整应用链路样例在 Start，跨项目 E2E 由对应项目维护 |

本表用于定位，不重新定义[架构约束](../../ARCHITECTURE.md)。不要把建议结构写成已有实现。

## 修改纪律

- 保持 API、配置与数据语义的兼容性；破坏性变化先说明影响和迁移方式，不能默默改变调用方约定。
- 修复缺陷先建立可复现证据；行为变化补对应回归测试，覆盖关键正常路径、边界和失败场景。文字及链接修订使用文档检查。
- 修改领域或协议对象时核对转换链路、校验及返回形状；不得通过跨层直接依赖省略边界。
- 数据库迁移保留已执行版本的语义与校验和，演进使用新迁移；现有副本问题未解决前不能只看一处就断言运行结果。
- 格式化属于会修改文件的动作，执行后复核差异；不混入全仓库无关格式改动。多人或代理共用工作区时避免并行 clean 覆盖彼此报告。
- 范围外问题登记已有技术债，不借当前任务顺带扩大实现。

## 按改动验证

| 改动 | 所需证据 |
| --- | --- |
| 纯文档 | 本次文件的格式、链接、导航和事实核对；`git diff --check` |
| 局部逻辑 | 相关单测及受影响模块检查；明确尚未覆盖的集成行为 |
| 接口、持久化或配置 | 对应契约与集成场景；需真实数据库或完整上下文的结论不能由 mock 替代 |
| 跨模块或依赖变化 | 受影响模块构建、兼容性及适用回归验证 |

常用 Maven 命令：

```bash
# 模块单测示例；同时构建所需 Reactor 依赖
./mvnw -pl app -am test

# 项目构建及测试生命周期；以实际报告判断覆盖范围
./mvnw clean verify

# 显式修改格式，随后复核差异
./mvnw spotless:apply
```

本项目默认 dev 配置会执行格式化，并跳过 Spotless check 与 JaCoCo；命令成功不等于全部格式、覆盖率和集成验收通过。检查时读取实际启用配置及本轮报告，不把其他仓库的命令行为套用到这里。数据库集成测试需要对应运行环境，跳过时明确说明。

## 交付

说明改了什么、为何修改、实际验证和未覆盖范围；结果应对应当前工作区或提交。简单任务在回复中说明，复杂任务补充已有计划的验收摘要。

同步受影响的使用说明与索引。提交、推送、合并、发布各自依用户明确授权执行；验证通过和文档登记本身不产生操作授权。
